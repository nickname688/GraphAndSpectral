# 研究工作台 MVP

## 产品定位

这个 App 是一个面向图论与谱图理论研究生、老师的本地优先研究工作台。它应该足够简单，适合个人日常使用，同时帮助用户把研究方向、论文、笔记和图计算记录放在一个地方管理。

这个 App 不应该承诺成为一个强大的 NP 难问题求解器。计算工具主要用于小例子、验证想法和记录实验；核心价值是研究资料管理。

## MVP 范围

第一版应该先打通一个完整的本地工作流：

1. 自动创建默认本地资料库。
2. 创建、查看、编辑、重命名、删除研究方向。
3. 为每个研究方向生成一个主文件 `direction.md`。
4. 在每个研究方向下保存轻量论文、笔记和计算记录。
5. 保留现有图计算器和超图计算器作为独立工具。
6. 支持把有用的图或超图计算结果保存到某个研究方向。

全局搜索很有用，但可以等第一版核心流程可用之后再做。

## 导航结构

底部导航应该从“计算器优先”调整为“研究工作台优先”：

```text
方向
工具
论文
设置
```

`工具` 中放现有的图谱半径计算器和超图谱半径计算器。计算器仍然作为独立工具页存在，只增加一个“保存计算记录到研究方向”的出口。

## 本地资料库结构

第一版自动创建并使用默认的 App 本地资料库。先不做自定义文件夹选择，因为跨平台文件访问会带来额外复杂度。

推荐目录结构：

```text
GraphSpectralLibrary/
  library.json
  directions/
    20260429-154233-spectral-radius/
      direction.json
      direction.md
      papers/
      notes/
      computations/
```

研究方向的文件夹名由程序自动生成，使用时间戳加简单 slug。用户只需要看到和编辑标题、简介。

## 研究方向元数据

研究方向的元数据保持极简：

```json
{
  "id": "20260429-154233-spectral-radius",
  "title": "谱半径相关问题",
  "summary": "关于上下界、极值图和相关猜想的资料。",
  "createdAt": "2026-04-29T15:42:33",
  "updatedAt": "2026-04-29T15:42:33"
}
```

MVP 阶段先不加入标签、颜色、负责人、排序权重、状态等字段，除非实现过程中证明它们确实必要。

## 研究方向内容

每个研究方向应该像一个简单的增强文件夹：

```text
direction.md
papers/
notes/
computations/
```

`direction.md` 是这个方向的主 Markdown 页面。第一版应支持 LaTeX 公式渲染，因为公式对目标用户非常关键。

推荐的 `direction.md` 默认模板：

```markdown
# 方向标题

## 已知边界

### 已有定理

### 经典论文

### 常用技巧

### 已知反例

## 当前前沿

### 未解决问题

### 我的猜想

### 可尝试的计算实验
```

## 论文、笔记和计算记录

三类内容需要区分，但实现要轻：

- 论文：本地 PDF，加一个简单 Markdown 笔记。
- 笔记：独立 Markdown 文件。
- 计算记录：从图或超图工具导出的 Markdown 记录。

MVP 阶段不要做成类似 Zotero 的文献管理器。BibTeX 导入、DOI 查询、在线元数据抓取、引用格式生成、PDF 正文搜索都先不做。

## 现有工具集成

当前 App 已经有图和超图计算器逻辑。图工具目前包括：

- `GraphCore`：无向简单图核心，保留孤立点。
- `GraphGenerator`：预设图，例如 `P4`、`C3/K3`、`C4`、`C5`、`K4`、`K5`、`S5`、`W5`。
- 命令输入、手动增边/删边、删点、自动计算、预设图选择、图可视化。
- 当前图计算重点是邻接矩阵谱半径、PF 向量和邻接矩阵输出。

MVP 应该复用这些工具，不重新设计图输入。等本地资料库和研究方向模型完成后，再给工具页增加导出/保存能力。

## 暂缓功能

以下功能等第一版本地工作流跑通后再考虑：

- 自定义资料库文件夹。
- 云同步、账号、共享资料库或 Git 工作流。
- 从论文或笔记中做 AI 抽取。
- 高级全文搜索和 PDF 正文搜索。
- 复杂标签、状态、仪表盘或统计。
- Zotero 式文献管理。
- 大规模图搜索或 NP 难优化工具。

## 第一阶段实现顺序

先实现本地资料库骨架和研究方向 CRUD：

1. 定义资料库和研究方向的 common 层模型。
2. 增加默认 App 本地资料库根目录的平台抽象。
3. 实现资料库初始化。
4. 实现研究方向的创建、读取、更新、删除。
5. 增加方向列表和方向详情入口。
6. 创建方向时自动生成 `direction.md`、`papers/`、`notes/`、`computations/`。
